## 1. 结论

当前棒已经实测兼容文章[《可遥控应援棒的控制信号》](https://www.bilibili.com/opus/980740947264405513)所述的短命令族，但现场使用的是D8开头的命令。不能说现场协议与文章只有一种完全相同的帧布局：

- `00` 7-byte 分区命令可以直接控制颜色和状态。
- 当前棒确定读取 **A 区**：A-only 命中，B-only、I-only 和空掩码均不命中。
- 文章列出的 16 个离散色码全部命中。
- 状态 `0..6` 的暗、常亮、三档闪烁、Fade in、Fade out 均已观察到。
- `color=AA` 保持颜色、`state=0B` 保持状态，均已验证。
- `C0` 的 A-J 独立色槽格式可用；当前棒读取其中的 A 槽。仅有一支 A 区棒，无法验证 B-J，更无法补出 K-P。
- `A6 07 43` 可使当前棒短促发出浅绿光并自动熄灭。
- `DA` 的帧格式和校验可以确定；“解锁实体按键”已通过软件发送 `DA` 后手动按键，当前棒确认解锁。
- 现场录制并经实物回放命中的 `D8` 21-byte 帧仍然有效；`D8` 应称为一种 command/type，不能再称为所有空口帧的固定帧头。
- `D8` 可按 `W0..W8` 九个位置槽描述；当前 A 区棒使 `W0 ≈ A` 成为强候选，`W1..W8 ≈ B..I` 仍是待验证的工作假设。

两类已响应命令的能力互补：

| 能力 | `00/C0/A6/DA` 短命令族 | `D8` 21-byte 命令 |
| --- | --- | --- |
| 颜色 | 16 色调色板 | 每个 RGB 分量 4 bit，共 4096 组合 |
| 常亮/闪烁 | `state=1..4` | `function=0..3` |
| 暗 | `state=0` | RGB 全零 |
| Fade in/out | 已验证，`state=5/6` | 未发现对应 canonical function |
| 地址/分区 | A-P 掩码；当前棒为 A | 九个位置槽；`W0≈A` 是强候选，后八槽暂拟 B-I |
| 独立多区颜色 | `C0` 明确覆盖 A-J | 单棒测试不能解释其余 word |
| 全局短脉冲 | `A6` 已验证 | 未确认 |
| 实体按键解锁 | `DA` 已验证 | 未确认 |

## 2. 证据

 **当前棒空口命令：** 已观察并回放成功的 `00/C0/A6` 短命令和 `D8` 21-byte 命令，使用相同的 `0x96` 加法校验族与相同 OOK 位编码。

## 3. 通用空口编码

文章给出的位串规则与本次可用的 CC1101 波形一致：

```text
raw = 11111111000011110 + concat("01" + d for each payload bit d)
```

其中 payload 包含该命令的全部字节和末尾校验；每字节 MSB first，`d` 是原数据位。

| 项目 | 当前结果 |
| --- | --- |
| 载波 | `433.920 MHz`；CC1101 实际读回约 `433.919840 MHz` |
| 调制 | ASK/OOK |
| 文章标称基础 bit | 约 `254 us`，即约 `3936 bps` |
| 本次成功使用的基础 bit | `250 us` |
| CC1101 起始电平 | `1` |
| 数据 0 的交替 duration | `[250 us, 500 us]` |
| 数据 1 的交替 duration | `[500 us, 250 us]` |
| 标准前缀的 duration 表示 | `[2000, 1000, 1000, 500] us`，末段已与首个数据前导 0 合并 |
| 兼容性观察 | 把首个 `2000 us` 高电平延长为 `16600 us`，当前棒仍可接收短命令 |

`2 ms` 前导最接近文章原始位串，也与现场 `D8` 帧约 `131.1 ms` 的起始间隔相容；`16.6 ms` 只应记作当前棒接受的延长唤醒包络，不是文章或现场的固定要求。

## 4. 加法校验

所有已识别命令均把校验放在最后一个字节：

```text
checksum = (0x96 + sum(all preceding frame bytes)) & 0xff
```

当前棒严格检查该值。棒为绿色时：

```text
正确红色：00 FF FF FF 01 00 94
错误校验：00 FF FF FF 01 00 95
```

发送错误帧后棒不响应命令；随后只发送一帧正确命令，棒正确响应了命令。

## 5. `00` 分区颜色/状态命令

### 5.1 布局

```text
00 M1 M2 X S C K
```

| 字节 | 含义 |
| --- | --- |
| `00` | command/type |
| `M1` | A-H 掩码：bit0=A，...，bit7=H |
| `M2` | I-P 掩码：bit0=I，...，bit7=P |
| `X` | 文章通常写 `FF`；当前棒在 A-only 测试中也接受 `00` |
| `S` | 状态码 |
| `C` | 色码或 `AA` 保持原色 |
| `K` | 加法校验 |

掩码中可以同时置多个 bit；`FF FF` 选择 A-P 全部区域。当前只有一支 A 区棒，因此“同时选中”仅证明 A 会响应，不能代替多区实物验证。

`X=00` 的实测帧为 `00 01 00 00 01 00 98`；它仍把当前 A 区棒置为常亮红色。该结果只说明当前批次忽略或兼容此字节，正式发送仍优先使用文章给出的 `FF`。

### 5.2 状态码

| `S` | 文章含义 | 当前棒验证 |
| ---: | --- | --- |
| `00` | 暗 | 已验证；`00 FF FF FF 00 00 93` 熄灭 |
| `01` | 常亮 | 已验证 |
| `02` | 慢闪 | 已验证；30 fps 下半周期约 17 帧，约 `0.88 Hz` |
| `03` | 中闪 | 已验证；半周期约 5 帧，约 `3.0 Hz` |
| `04` | 快闪 | 已验证；半周期约 2-3 帧，约 `6.0 Hz` |
| `05` | Fade in | 已验证；从暗态渐亮并停在目标色 |
| `06` | Fade out | 已验证；从目标色渐暗并停在暗态 |
| `0B` | 状态不变 | 已验证；慢闪红改为绿色后仍保持约 17 帧半周期 |

Fade 测试使用了六次重复，所以当前证据证明动作和最终状态，不把采样到的过渡时长当成设备的精确单次动画参数。

### 5.3 16 色调色板

相机值用于状态判别，不是光学标定值；文章的颜色名称也只是近似描述。

| `C` | 文章名称 | 当前棒相机 RGB |
| ---: | --- | --- |
| `0` | 红 | `[155,0,0]` |
| `1` | 绿 | `[0,141,26]` |
| `2` | 蓝 | `[24,120,255]` |
| `3` | 粉 | `[160,0,108]` |
| `4` | 白 | `[101,114,245]` |
| `5` | 黄 | `[95,75,7]` |
| `6` | 浅蓝 | `[32,107,255]` |
| `7` | 浅绿 | `[0,126,73]` |
| `8` | 紫 | `[119,44,255]` |
| `9` | 橙 | `[149,0,0]` |
| `A` | 浅粉 | `[135,0,149]` |
| `B` | 较深蓝 | `[27,144,255]` |
| `C` | 浅黄 | `[87,71,65]` |
| `D` | 较深绿 | `[0,111,102]` |
| `E` | 浅红 | `[92,0,46]` |
| `F` | 更亮白 | `[195,211,255]` |

`C=AA` 是“颜色不变”哨兵，不是 4-bit 调色板索引。绿色状态下发送 `00 FF FF FF 01 AA 3E` 后，棒保持约 `[0,135,23]`。

## 6. 分区验证

先把当前棒设为绿色，再发下列红色命令：

| 测试 | 帧 | 相机结果 | 结论 |
| --- | --- | --- | --- |
| A-only | `00 01 00 FF 01 00 97` | 变红约 `[154,0,0]` | 命中 |
| B-only | `00 02 00 FF 01 00 98` | 保持绿 | 不命中 |
| I-only | `00 00 01 FF 01 00 97` | `[0,135,24]`，保持绿 | 第二掩码字节不命中当前棒 |
| 空掩码 | `00 00 00 FF 01 00 96` | 保持绿 | 无区域时不执行 |

所以当前棒的地址分区是 **A**。这证明棒和短协议具备分区能力；它不证明活动现场一定使用了多套不同灯效。

## 7. `C0` A-J 独立颜色命令

```text
C0 AB CD EF GH IJ K
```

五个 payload 字节的高、低 nibble 依次给 A、B、C、D、E、F、G、H、I、J 指定 4-bit 色码，最后是同一加法校验。

已发送：

```text
C0 01 23 45 67 89 AF
```

它把 A-J 分别指定为色码 `0..9`。当前棒变为红色 `[155,0,0]`，与 A 槽的高 nibble `0` 一致，进一步确认当前棒为 A。文章和当前单棒实验都没有给出 `C0` 对 K-P 的编码，不能擅自外推。

## 8. `A6` 全局型短脉冲命令

```text
A6 C K
```

该命令没有分区掩码。当前验证例：

```text
A6 07 43
```

棒从暗态发出浅绿短脉冲，峰值约 `[0,159,99]`，随后自动恢复暗态。六次重复的 30 fps 录像中只出现短亮段，没有留下持续颜色。由于只有一支棒，本文只确认当前棒会响应，不能把文章所称“所有棒”升级为多棒实测结论。

## 9. `DA` 实体按键解锁命令

文章格式：

```text
DA M1 M2 X1 X2 X3 K
```

`M1/M2` 使用相同 A-P 掩码；文章称后三个 payload 字节不影响解锁，但仍参与校验。全区示例为：

```text
DA FF FF FF 01 00 6E
```

该功能的判据是“发射后实体按键恢复可用”。当前棒已通过软件发射
`DA FF FF FF 01 00 6E` 后手动按键确认解锁。

## 10. 现场 `D8` 21-byte 命令

现场录制和此前实物回放证明当前棒还接受另一种 21-byte 布局：

```text
D8 W0_hi W0_lo W1_hi W1_lo ... W8_hi W8_lo PHASE K
```

共 21 bytes：`D8` type、9 个按位置排列的 16-bit 控制槽 `W0..W8`、一个
`PHASE` 和一个校验 `K`。`K` 仍是从 `0x96` 开始对前 20 bytes 求和。

这里的 `W0..W8` 是当前证据支持的候选结构，不是已经完成命名的协议字段。
每个槽的 `0000` 是该槽的控制值，不能据此把它解释成组别编号，也不能把
所有未使用槽简单标成已证实的 padding。当前高质量现场帧恰好只有 `W0` 非零，
所以只能看到一个活动槽。

### 10.1 连续 RGB 控制字

先构造逻辑字：

```text
W = FFFF RRRR GGGG BBBB
A = ROL16(W, 2)
```

每个 RGB nibble 为 `0..15`。例如 `#66CCFF`：

```text
W = 06CF
A = 1B3C
```

canonical function：

| `F` | 当前棒行为 | 对应短命令状态 |
| ---: | --- | ---: |
| `0` | 常亮 | `1` |
| `1` | 约 0.89 Hz 闪烁 | `2` |
| `2` | 约 3.08 Hz 闪烁 | `3` |
| `3` | 约 6.10 Hz 闪烁 | `4` |

`F=4..15` 在合成测试中大致按 `F & 3` 别名复用，但没有现场原始帧依据，正式控制只应使用 `0..3`。

### 10.2 组别槽位的当前推测

结合短命令对 A 区的实测确认，以及当前棒在 D8 测试中服从第一个控制字，
当前最强的工作假设是：

```text
W0 ≈ A
W1 ≈ B
W2 ≈ C
W3 ≈ D
W4 ≈ E
W5 ≈ F
W6 ≈ G
W7 ≈ H
W8 ≈ I
```

其中 `W0 ≈ A` 是当前单支 A 区棒上已经得到的强候选；`W1..W8 ≈ B..I`
仍待其他分区实物或后续现场帧验证。逐一把后八个 2-byte 位置改成红色时，
当前棒仍服从首个绿色控制字；九个位置全写蓝色时棒变蓝，但首个位置本身
已足够解释结果。因此这些测试支持“按位置排列的槽位”模型，却不能单独证明
后八槽就是短协议的 B-I。

这个推测还存在一个必须保留的结构矛盾：`C0` 明确有 A-J 十个固定颜色槽，
而 `00`/`DA` 的掩码支持 A-P 十六个分区，D8 空口帧却只容纳九个 16-bit 槽。
因此也不能排除另一种候选解释：一个全局颜色/功能槽加上八个覆盖、地址或
其他用途的槽。需要其他分区棒，或一条后续槽位非零且彼此不同的原始帧，
才能继续收敛映射。

### 10.3 phase 和连续事务

现场 phase 大量呈 `2 -> 1 -> 0`。本次交付把六帧组合成一次连续发射事务，
在事务内发送两个完整周期：

```text
2, 1, 0, 2, 1, 0
```

六个帧仍然各自是完整空口帧，并分别重算 `K`；第二个 `2,1,0` 周期是可靠性
冗余，不代表三个 phase 是三个不同的功能步骤。固定重复一个 phase 可能被棒
当作重复帧而不更新。单帧、一个 `2,1,0` 周期和其他重复策略尚未做对照实验，
所以六帧不是已证明的最低要求。

现场记录中的约 `131.1 ms` 是相邻帧的**起始到起始**间隔，不是帧后的纯低电平
间隔。本程序在 `T=250 us` 时生成的 21-byte 帧长 `130.25 ms`，因此连续事务在
两帧之间补约 `850 us` 低电平。六帧合计约 `785.75 ms`，作为一条
`TX_PULSES` 请求提交，外层 `repeat=1`。

`D8` 是有效 type，而不是全局固定帧头。它与短命令共享物理编码和校验族，较可能属于同一接收器支持的另一种 command，但目前没有足够证据定义所有 type 的统一上层语法。

## 11. 推荐发送事务

### 11.1 短命令

1. 选择 `00`、`C0`、`A6` 或 `DA` 格式并填入字段。
2. 对最后一个校验字节之前的所有 bytes 加总，再加 `0x96`，取低 8 bit。
3. 每字节 MSB first，按前缀和 `01d` 规则生成 OOK 波形；当前验证使用 `T=250 us`。
4. 普通常亮红的单帧事务为 116 个 duration、约 `46.5 ms`，已单帧命中。
5. 为提高可靠性和执行 Fade/脉冲，推荐同一完整帧重复 6 次，帧间保持约 `20 ms` 低电平；7-byte 命令总时长约 `379 ms`。文章只说明“重复数次”，重复次数不是帧字段。

### 11.2 `D8` 命令

1. 根据 RGB 和 canonical `F` 计算 `A=ROL16(W,2)`。
2. 将控制字放入候选槽位 `W0..W8`；当前 A 区棒的默认槽位是 `W0`，其余槽位映射仍按上节的工作假设处理。
3. 将六帧组合成一次连续事务，phase 依次为 `2,1,0,2,1,0`，并为每个独立帧重算校验；后一个周期用于冗余，不是已证明的协议最低帧数。
4. 使用相同的 MSB-first OOK 编码。现场约 `131.1 ms` 的帧起始间隔与标准短前导相容；此前延长前导回放也可命中当前棒。

### 11.3 发射安全

本次近距离验证条件：

- `433.920 MHz`
- `-20 dBm`
- 通过 `TX_PULSES` 返回的 `request_id` 轮询 `GET_TX_RESULT`，直到明确得到 `success` 或 `error`
- 超时先 `ABORT`，再确认对应 TX 结果为 `error`

这些是实验室近距离可用条件，不是远距离链路预算或当地法规允许功率的结论。


## 12. 尚未确认的边界

- `DA` 已通过软件发射并手动按键确认当前棒解锁；其他批次或型号的棒仍需独立验证。
- `C0` 对 K-P 的编码，以及 B-P 实物响应，需其他分区的棒。
- `00` 命令中 `X` 字节在其他批次棒上的意义未知；只确认当前棒接受 `FF` 和 `00`。
- `D8` 后八个 2-byte 槽是否确为 B-I、九槽如何对应 A-P，以及是否存在其他 command/type 仍待验证；“全局槽+八个覆盖/地址槽”仍是备选解释。
- 评论区关于其他批次校验初值 `0x86` 的说法没有当前实物证据，不纳入本协议。
- 绝对载频误差、最大距离、抗干扰性和法规功率未测量。

## 13. 最终状态要求

每轮验证结束应恢复 `00 FF FF FF 01 01 95` 常亮绿，并确认：

```text
tx_busy  = false
MARCSTATE = 1 (IDLE)
```

本轮结束时连续 8 帧相机样本均为 `[0,140,25]`；上述状态已实际读回，随后发送会话断开串口。
